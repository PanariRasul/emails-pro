# Deploying Emails Pro (Render Free + Neon Free)

Allow about 30 minutes. You need a GitHub account, a Render account and a Neon account (all free).

```
Browser ──► Render Static Site (React)  ──/api/* rewrite──►  Render Web Service (Express API + worker)
                                                                  │        │
                                                     Neon Postgres (pooled)  Gmail API / SES API (HTTPS)
                                                                             IMAP :993 (replies)
```

---

## 1. Push the code to GitHub

```bash
cd emails-pro
git init && git add . && git commit -m "Emails Pro"
git branch -M main
git remote add origin https://github.com/<you>/emails-pro.git
git push -u origin main
```

No secret files are committed: configuration lives only in Render's environment settings.

## 2. Create the Neon database

1. Neon Console → **New project**. Choose the region closest to your Render region (e.g. *AWS Asia Pacific (Singapore)* for Render *Singapore*).
2. On the project dashboard click **Connect** and copy two connection strings:
   - **Pooled** (host contains `-pooler`) → this becomes `DATABASE_URL`
   - **Direct** (toggle "Connection pooling" off) → this becomes `DIRECT_URL`
3. Both must include `sslmode=require`. If the string contains `&channel_binding=require` and you see connection errors, remove that parameter.

> Migrations run through `DIRECT_URL`; the app uses the pooled `DATABASE_URL` with a small pool (`DB_POOL_MAX=5`).

## 3. Generate the encryption key (keep a backup)

```bash
openssl rand -base64 32
```

Store this value in your password manager. **If `ENCRYPTION_KEY` is lost, every saved SMTP/IMAP password and OAuth token becomes unreadable** and employees must reconnect their accounts. (To rotate it, see *Operations → Rotating the encryption key*.)

## 4. Deploy with the Blueprint

1. Render Dashboard → **New → Blueprint** → select the repository. Render reads `render.yaml` and proposes two services: `emails-pro-api` (Free Web Service) and `emails-pro-web` (Static Site).
2. Fill in the prompted environment values:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon **pooled** connection string |
| `DIRECT_URL` | Neon **direct** connection string |
| `ENCRYPTION_KEY` | the key from step 3 |
| `PUBLIC_API_URL` | `https://emails-pro-api.onrender.com` (your API's URL) |
| `CORS_ORIGINS` | `https://emails-pro-web.onrender.com` (your frontend URL; comma-separate several) |
| `BOOTSTRAP_ADMIN_EMAIL` | your admin email |
| `BOOTSTRAP_ADMIN_PASSWORD` | a strong password (≥ 12 characters) |

`JWT_SECRET` and `TRACKING_SECRET` are generated by Render automatically.

3. **If Render assigned a different API hostname** (because `emails-pro-api` was taken), edit the `/api/*` rewrite destination in `render.yaml` (or in the static site's *Redirects/Rewrites* settings) and update `PUBLIC_API_URL`.
4. Click **Apply**. The API build runs `npm ci`, `prisma generate` and **`prisma migrate deploy`**, which applies committed migrations only and never resets data.

### Manual setup (without the Blueprint)

**Backend** → New → Web Service → repo → *Root directory* `backend`, *Runtime* Node, *Instance type* **Free**
- Build command: `npm ci --omit=dev && npx prisma generate && npx prisma migrate deploy`
- Start command: `npm start`
- Health check path: `/health`
- Environment: as in the table above plus `NODE_ENV=production`, `NODE_VERSION=22`, `JWT_SECRET`, `TRACKING_SECRET` (long random strings).

**Frontend** → New → Static Site → repo → *Root directory* `frontend`
- Build command: `npm ci && npm run build`
- Publish directory: `dist`
- Redirects/Rewrites (order matters):
  1. Rewrite `/api/*` → `https://<your-api>.onrender.com/api/*`
  2. Rewrite `/*` → `/index.html`

HTTPS is automatic on both services.

## 5. First login

1. Open the frontend URL. The first request may take up to a minute while the API wakes up; the app shows "Connecting to Emails Pro…".
2. Sign in with the bootstrap admin credentials.
3. **Remove `BOOTSTRAP_ADMIN_PASSWORD`** from the API environment (it is only used when no admin exists).
4. Admin → *Policies & settings*: review the defaults (100 accounts, 500/day, 60/hour per account, 7 working campaigns).
5. Admin → *Employees* → create employees.

## 6. Choose how accounts will send (important on Render Free)

Render Free **blocks outbound SMTP on ports 25, 465 and 587**. The app detects this, and *System health* shows "Outbound SMTP: Blocked".

| Option | Cost | Setup |
|---|---|---|
| **Gmail / Google Workspace via Google sign-in** (Gmail API, HTTPS) | Free | Section 7 below |
| **Amazon SES API** (HTTPS) | SES pricing | Employee picks *Amazon SES → SES API*, enters region + IAM access key with `ses:SendRawEmail`/`ses:SendEmail` and `ses:GetAccount`. Verify the sending identity in SES first and leave the SES sandbox for real campaigns. |
| **SMTP relay on port 2525** | Provider pricing | Choose *Custom SMTP*, port 2525, STARTTLS. |
| **Zoho / Yahoo / Rediffmail / other SMTP on 465/587** | Render paid instance | Switch `emails-pro-api` to a paid instance type. No code changes are needed. |

Replies are read over IMAP (port 993), which works on the free plan.

## 7. Optional: Google sign-in (Gmail API sending)

1. Google Cloud Console → create a project → **APIs & Services → Enable APIs** → enable **Gmail API**.
2. **OAuth consent screen**: External (or Internal for Workspace). Add the scope `https://mail.google.com/`. While the app is in *Testing* mode, add each employee's Google address as a test user. (Publishing an app that requests this restricted scope requires Google's verification.)
3. **Credentials → Create OAuth client ID → Web application**:
   - Authorized redirect URI: `https://<your-api>.onrender.com/api/oauth/google/callback`
4. Add `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` to the API environment and redeploy.
5. Employees now see **Sign in with Google** when connecting Gmail/Workspace accounts.

## 7b. Email OTP sign-in and password reset

Codes are sent from a **system mailbox** (default `emailspro.otp@gmail.com`) to each user's own account email.

1. Admin → *Policies & settings* → **Login security**.
2. Connect the mailbox:
   - **On Render Free (recommended): “Connect with Google”**, signing in as emailspro.otp@gmail.com. Codes go out through the Gmail API over HTTPS. This needs the Google OAuth client from section 7.
   - **Locally / on a paid instance:** turn on 2-Step Verification for the Gmail account, create an **App Password**, and set `SYSTEM_MAIL_APP_PASSWORD` in `backend/.env` (or the Render environment). Render Free blocks SMTP, so this method can't send there.
3. Use **Send test** to confirm delivery, then switch on **Email OTP for employees**. Requiring codes for admins is optional. The app refuses to enable OTP while no mailbox is configured.
4. The same mailbox powers **Forgot password?** on the sign-in page.

Codes are 6 digits, valid for 10 minutes, allow 5 attempts, can be resent after 45 seconds, and are stored only as an HMAC.

### “Continue with Google / Microsoft” on the sign-in page (optional)
These buttons appear only when configured, and they sign in **existing** users only (no self-registration).
- Google: reuse the OAuth client from section 7 and add the redirect URI `https://<your-frontend>.onrender.com/api/auth/sso/google/callback`.
- Microsoft: register an app in Microsoft Entra ID with redirect URI `https://<your-frontend>.onrender.com/api/auth/sso/microsoft/callback`, then set `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` and `MICROSOFT_TENANT` (default `common`).
- Set `APP_URL` to your frontend URL.

## 8. Optional: Redis

Not required. If you have a Redis-compatible service you trust, set `REDIS_URL`. It is used only for shared request rate limiting and appears in readiness checks. Losing Redis never loses campaign data.

## 9. Verify the deployment

| Check | How |
|---|---|
| API is up | `https://<api>/health` → `{"status":"ok","app":"Emails Pro",…}` |
| DB + worker ready | `https://<api>/ready` → `"status":"ready"` |
| Frontend routing | open `https://<web>/campaigns` directly → app loads (SPA fallback) |
| Same-origin API | `https://<web>/api/health` returns the same JSON |
| SMTP egress status | Admin → *System health* → "Outbound SMTP" |
| Sending | connect an account → *Test* → *Test email* |

Then run through the full checklist in [OPERATIONS.md](OPERATIONS.md#pre-launch-test-checklist).

## Environment variable reference

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `DATABASE_URL` | ✅ | – | Neon pooled connection string (runtime) |
| `DIRECT_URL` | ✅ | – | Neon direct connection string (migrations) |
| `JWT_SECRET` | ✅ | – | Signs access tokens (≥ 32 chars) |
| `ENCRYPTION_KEY` | ✅ | – | 32-byte base64 key for AES-256-GCM credential encryption |
| `ENCRYPTION_KEY_PREVIOUS` | – | – | Previous key during rotation |
| `TRACKING_SECRET` | – | `JWT_SECRET` | Signs click-tracking links |
| `PUBLIC_API_URL` | ✅ | Render URL | Base URL embedded in tracking/unsubscribe links |
| `CORS_ORIGINS` | ✅ | – | Allowed frontend origins (comma-separated) |
| `BOOTSTRAP_ADMIN_EMAIL` / `_PASSWORD` | first deploy | – | Creates the first admin if none exists |
| `GOOGLE_CLIENT_ID` / `_SECRET` | – | – | Google sign-in → Gmail API sending, OTP mailbox, “Continue with Google” |
| `APP_URL` | – | first CORS origin | Frontend URL used for SSO redirects |
| `SYSTEM_MAIL_USER` | – | `emailspro.otp@gmail.com` | Mailbox that sends OTP / reset codes |
| `SYSTEM_MAIL_APP_PASSWORD` | – | – | Gmail app password (SMTP; local/paid hosting only) |
| `SYSTEM_MAIL_HOST` / `_PORT` / `_SECURE` | – | `smtp.gmail.com` / `465` / `true` | SMTP server for the system mailbox |
| `MICROSOFT_CLIENT_ID` / `_SECRET` / `_TENANT` | – | – / – / `common` | “Continue with Microsoft” |
| `REDIS_URL` | – | – | Optional shared rate limiting |
| `DB_POOL_MAX` | – | `5` | pg pool size |
| `RUN_WORKER` | – | `true` | Disable to run the worker elsewhere |
| `WORKER_TICK_MS` / `WORKER_IDLE_TICK_MS` | – | `5000` / `60000` | Worker loop intervals while sending / idle |
| `WORKER_BATCH_SIZE` | – | `5` | Max sends per tick |
| `STUCK_SENDING_MINUTES` | – | `10` | When an in-flight send is considered interrupted |
| `SMTP_TIMEOUT_MS` | – | `30000` | SMTP socket timeout |
| `ACCESS_TOKEN_TTL_SEC` / `REFRESH_TOKEN_TTL_DAYS` | – | `900` / `14` | Session lifetimes |
| `COOKIE_SAMESITE` | – | `none` (prod) | Refresh cookie SameSite |
| `LOG_LEVEL` | – | `info` | pino log level |

Frontend (build-time): `VITE_API_URL` is optional. Leave it unset to use the same-origin `/api` rewrite (recommended).
